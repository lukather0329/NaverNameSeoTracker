  있어서 데이터 소스 교체 자체는 아키텍처상 준비되어 있음.
- 순위 데이터를 앞으로 어디서 가져올지(수동 입력 / 저빈도 완화 / 판매지표로 프록시 전환 /
  유료 데이터 제공업체)는 아직 결정 안 됨 — 다음 세션에서 결정 필요.

1. 프로젝트 목적
현재 개발 중인 `NaverNameSeoTracker`를 단순 상품명 순위 추적 프로그램에서, 상품명·상세페이지·리뷰·변경 이력·순위 변화를 분석하는 네이버 쇼핑 AI SEO 분석 플랫폼으로 확장하려고 한다.
이번 작업에서는 화면 개발이나 네이버 API 연동을 우선하지 않는다.
먼저 여러 프로그램에서 공통으로 사용할 수 있는 독립적인 AI SEO 분석 엔진 라이브러리를 개발한다.
향후 다음 프로젝트에서 재사용할 수 있어야 한다.

* NaverNameSeoTracker
* 네이버 광고 분석 MVP
* OMS
* 상품명 SEO 최적화 프로그램
* 스마트스토어 상품관리 프로그램
* 통합 AI SEO 플랫폼

2. 이번 작업의 핵심 원칙
다음 원칙을 반드시 준수한다.

1. UI를 먼저 만들지 않는다.
2. 네이버 검색 순위 수집 기능을 새로 개발하지 않는다.
3. 기존 NaverNameSeoTracker 코드를 대규모 수정하지 않는다.
4. 독립적인 엔진 패키지로 개발한다.
5. 실제 네이버 내부 알고리즘 점수라고 표현하지 않는다.
6. 모든 점수는 공개 데이터와 내부 규칙에 기반한 추정치로 처리한다.
7. 점수뿐 아니라 점수 산출 근거를 반드시 반환한다.
8. 규칙 기반 분석과 LLM 기반 분석을 분리한다.
9. LLM이 없어도 기본 분석이 가능해야 한다.
10. 향후 Python, Node.js, React 프로젝트에서 모두 사용할 수 있도록 API 경계를 명확히 설계한다.

5. 공통 분석 결과 형식
모든 분석 엔진은 최대한 동일한 결과 구조를 사용한다.

```ts
export interface AnalysisResult<TDetails = unknown> {
  score: number;
  grade: "A" | "B" | "C" | "D" | "F";
  confidence: number;

  summary: string;

  strengths: AnalysisFinding[];
  weaknesses: AnalysisFinding[];
  recommendations: Recommendation[];

  details: TDetails;

  metadata: {
    engineVersion: string;
    analyzedAt: string;
    inputHash?: string;
    rulesetVersion?: string;
    llmUsed: boolean;
  };
}

export interface AnalysisFinding {
  code: string;
  title: string;
  description: string;
  evidence?: string[];
  weight?: number;
}

export interface Recommendation {
  code: string;
  priority: "HIGH" | "MEDIUM" | "LOW";
  title: string;
  description: string;
  expectedImpact?: {
    min: number;
    max: number;
  };
}

```

점수는 0~100 범위를 사용한다.
단, 점수만 반환하지 말고 반드시 다음 항목도 포함해야 한다.

* 왜 해당 점수가 나왔는지
* 어떤 요소가 긍정적으로 평가됐는지
* 어떤 요소가 부족한지
* 어떤 수정이 필요한지
* 분석 신뢰도가 어느 정도인지

6. Semantic Analyzer
목적
상품명을 입력받아 AI 또는 검색 시스템이 해당 상품을 어떤 의미로 해석할 가능성이 높은지 분석한다.
단순 키워드 개수 계산기가 아니라 다음 구조를 분석해야 한다.

* 브랜드
* 제품 유형
* 주요 기능
* 사용 대상
* 사용 목적
* 기술 또는 호환성
* 규격
* 차별 요소
* 카테고리 적합성
* 중복 표현
* 불필요한 홍보 문구
* 과도한 키워드 나열
* 누락된 핵심 속성

입력 예시

```ts
export interface SemanticAnalysisInput {
  productName: string;
  brand?: string;
  category?: string;
  attributes?: Record<string, string | number | boolean>;
  targetKeywords?: string[];
  prohibitedKeywords?: string[];
  competitorNames?: string[];
}

```

출력 예시

```ts
export interface SemanticAnalysisDetails {
  entities: {
    brand?: string;
    productType?: string;
    functions: string[];
    targetUsers: string[];
    useCases: string[];
    technologies: string[];
    specifications: string[];
    modifiers: string[];
  };

  matchedKeywords: string[];
  missingKeywords: string[];
  duplicatedTerms: string[];
  suspiciousTerms: string[];
  categoryAlignmentScore: number;
  clarityScore: number;
  keywordBalanceScore: number;
  readabilityScore: number;
}

```

기본 규칙
최소한 다음을 규칙 기반으로 구현한다.

1. 상품명이 지나치게 짧은지
2. 상품명이 지나치게 긴지
3. 브랜드가 포함됐는지
4. 제품 유형이 명확한지
5. 핵심 키워드가 포함됐는지
6. 동일 단어가 반복되는지
7. 특수문자가 과도한지
8. 광고성 표현이 과도한지
9. 카테고리와 상품명이 일치하는지
10. 주요 속성이 누락됐는지
11. 검색 의도를 이해하기 쉬운 구조인지
12. 브랜드명만 있고 제품 설명이 없는지

광고성 표현 예시:

* 최고
* 최저가
* 대박
* 인기
* 추천
* 무료배송
* 한정특가
* 베스트
* 1위

이 목록은 하드코딩하지 말고 설정 파일 또는 규칙 파일에서 관리한다.
예시
입력:

```json
{
  "productName": "허밍버드PRO",
  "brand": "메이크웨어",
  "category": "교육용 코딩드론",
  "targetKeywords": [
    "코딩드론",
    "파이썬",
    "교육용 드론",
    "AI 드론"
  ]
}

```

예상 분석:

```text
브랜드 또는 모델명만 존재하여 제품 유형을 이해하기 어렵다.
코딩드론, 교육용, 파이썬 관련 의미가 부족하다.
제품명만으로 사용 대상과 목적을 판단하기 어렵다.

```

추천 상품명 예시를 자동 생성하는 기능은 인터페이스만 우선 준비한다.

```ts
generateSuggestions(
  input: SemanticAnalysisInput,
  options?: SuggestionOptions

export interface ContentQualityInput {

```

분석 항목
다음 항목을 분석한다.

* 전체 텍스트 길이
* 실제 설명 텍스트 비율
* 제목과 소제목 구조

9. Ranking Change Detector
목적
상품 순위가 변했을 때 단순히 상승 또는 하락을 기록하는 것이 아니라, 변경 이력과의 시간 관계를 분석해 원인 후보를 제시한다.
이 엔진은 "원인을 확정"해서는 안 된다.
반드시 다음과 같이 표현해야 한다.

* 원인 후보
* 상관관계
* 추정 영향
* 신뢰도
* 분석 근거

분석 항목
다음 분석을 구현한다.

11. 요일 또는 시간대 변동 가능성
12. 비교 가능한 데이터가 충분한지

12. Confidence Score
분석 점수와 신뢰도를 구분한다.
예:

* 상품명만 입력됨: 분석 점수는 계산 가능하지만 신뢰도는 낮음
* 카테고리, 속성, 목표 키워드까지 입력됨: 신뢰도 상승
* 순위 데이터가 3개뿐임: Ranking Change Detector 신뢰도 낮음
* 순위 데이터가 100개이고 변경 전후 기간이 충분함: 신뢰도 높음

신뢰도는 다음 요소를 반영한다.

* 입력 데이터 완성도
* 표본 수
* 데이터 누락률
* 분석 규칙 적용 가능성
* LLM 결과와 규칙 결과의 일치도
* 비교 기간의 적절성
