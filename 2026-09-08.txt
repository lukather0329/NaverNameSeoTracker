2. **Experiment Manager Prisma 매핑 어댑터 구현** (9/7 우선순위 #1):
   - apps/server/src/services/ai-seo-engine-adapter.ts에
     mapSeoExperimentToEngineExperiment() 신설. 기존 Prisma SeoExperiment 모델은
     "상품명 변경 실험" 전용(beforeTitle/afterTitle 문자열만 저장)이라 엔진의
     SeoExperiment 타입이 갖는 hypothesis/baselinePeriod/measurementPeriod/
     linkedRankingAnalysisIds 등은 원본 데이터가 없음 - 지어내지 않고 실제로
     알 수 있는 값만 채움(variableType은 "PRODUCT_NAME"으로 고정, hypothesis는
     notes가 있으면 그대로, 없으면 beforeTitle/afterTitle 기반 문구 자동생성).
   - 상태값 매핑(mapExperimentStatus): Prisma의 DRAFT/RUNNING/PAUSED/COMPLETED/FAILED가
     엔진의 DRAFT/SCHEDULED/RUNNING/COMPLETED/CANCELLED/ROLLED_BACK과 1:1 대응이
     안 돼서 PAUSED->SCHEDULED, FAILED->ROLLED_BACK으로 근사 매핑(주석에 근거 명시).
     이 매핑 결과는 엔진의 상태 전이 검증에는 다시 넣지 않고 타임라인/비교 같은
     읽기 전용 계산에만 사용하도록 범위를 제한함(기존 실험 CRUD 라우트는 손대지 않음 -
     "기존 코드 최소 변경" 지시사항 준수).
   - GET /api/products/:id/experiment-timeline 라우트 신설 (apps/server/src/routes/index.ts).
     ExperimentManager.buildTimeline()으로 실험 상태변화 타임라인을, compareSnapshots()로
     실험별 상품명 변경 전/후 diff를 함께 반환.
   - 실제 DB 데이터로 라이브 테스트: 텀블러 상품(2개 실험, 하나는 RUNNING/하나는 DRAFT)에
     대해 정상 동작 확인. 테스트 중 실제 버그 하나 발견해서 고침 - Prisma의 startDate가
     필수 필드라 DRAFT 상태에서도 항상 채워져 있는데, 이걸 그대로 startedAt에 매핑하면
     아직 시작도 안 한 DRAFT 실험에도 엔진이 허위 "실험 시작" 타임라인 이벤트를 만들어냄.
     appliedAt이 없고 status가 DRAFT면 startedAt을 비우도록 수정해서 해결.
   - 에러 경로도 실제로 확인: 존재하지 않는 상품 ID -> 404, 실험 없는 상품 -> 400.
